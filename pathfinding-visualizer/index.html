Breadth-First Search (BFS)

BFS explores all neighbors at the current depth before moving to the next level. Think of dropping a stone into still water — the ripple expands uniformly outward. Because it visits nodes in order of increasing distance, BFS guarantees the shortest path on unweighted grids.

Pseudocode

function BFS(start, end):
    queue ← [start]
    visited ← {start}
    parent ← {}

    while queue is not empty:
        node ← queue.dequeue()
        if node == end:
            return reconstructPath(parent, end)
        for neighbor in getNeighbors(node):
            if neighbor not in visited and not a wall:
                visited.add(neighbor)
                parent[neighbor] = node
                queue.enqueue(neighbor)
    return null   // no path found

Complexity

  • Time: O(V + E) — every vertex and edge processed at most once.
  • Space: O(V) — the queue and visited set can hold all vertices in the worst case.

Tradeoffs

BFS is simple, optimal for unweighted grids, and easy to implement. However, it explores in all directions equally, which wastes work when the goal is far away in a known direction. It also cannot handle weighted edges without modification.

Depth-First Search (DFS)

DFS picks a direction and goes as deep as possible before backtracking. It is not guaranteed to find the shortest path — it finds a path, which may be long and winding.

Pseudocode

function DFS(start, end):
    stack ← [start]
    visited ← {start}
    parent ← {}

    while stack is not empty:
        node ← stack.pop()
        if node == end:
            return reconstructPath(parent, end)
        for neighbor in getNeighbors(node):
            if neighbor not in visited and not a wall:
                visited.add(neighbor)
                parent[neighbor] = node
                stack.push(neighbor)
    return null

Complexity

  • Time: O(V + E)
  • Space: O(V) — the stack depth can reach V in the worst case.

Tradeoffs

DFS uses less memory than BFS on wide, shallow graphs because it only needs the current branch in memory. It is useful for maze generation and cycle detection, but a poor choice when shortest-path guarantees matter.

Dijkstra's Algorithm

Dijkstra expands the node closest to the start at every step, gradually building the shortest-path tree outward. It handles weighted edges (cells with different movement costs) and guarantees the shortest path for non-negative weights.

Pseudocode

function Dijkstra(start, end):
    dist[start] = 0            // all others = ∞
    pq ← MinHeap { start }

    while pq is not empty:
        node ← pq.extractMin()
        if node == end:
            return reconstructPath(parent, end)

        for neighbor in getNeighbors(node):
            alt = dist[node] + weight(node, neighbor)
            if alt < dist[neighbor]:
                dist[neighbor] = alt
                parent[neighbor] = node
                pq.decreaseKey(neighbor, alt)
    return null

Complexity

  • Time: O(V log V) with a binary heap, O(V²) with a naive array.
  • Space: O(V) for the distance table and priority queue.

Tradeoffs

On an unweighted grid Dijkstra degenerates to BFS with extra overhead. Its real strength is weighted terrain. Like BFS, it is "uninformed" — it has no notion of where the goal is, so it explores uniformly.

A* (A-Star) Algorithm

A* is an informed search that combines Dijkstra's actual cost g(n) with a heuristic estimate of remaining cost h(n). The total priority is f(n) = g(n) + h(n). With an admissible heuristic (one that never overestimates), A* guarantees the shortest path while typically visiting far fewer nodes than BFS or Dijkstra.

Pseudocode

function AStar(start, end):
    g[start] = 0
    f[start] = h(start, end)      // heuristic
    openSet ← MinHeap { start }   // keyed on f

    while openSet is not empty:
        node ← openSet.extractMin()
        if node == end:
            return reconstructPath(parent, end)

        for neighbor in getNeighbors(node):
            tentG = g[node] + weight(node, neighbor)
            if tentG < g[neighbor]:
                g[neighbor] = tentG
                f[neighbor] = tentG + h(neighbor, end)
                parent[neighbor] = node
                openSet.insertOrUpdate(neighbor)
    return null

Heuristic: Manhattan Distance

h(a, b) = |a.row − b.row| + |a.col − b.col|
Admissible for 4-directional movement (never overestimates). For 8-directional grids, use the Chebyshev or Octile distance instead.

Complexity

  • Time: O(V log V) worst-case, but typically much better because the heuristic prunes most of the search space.
  • Space: O(V)

Tradeoffs

A* is usually the best choice for grid pathfinding. The quality of the heuristic determines how much work it saves. A perfect heuristic makes it visit only the optimal path; a zero heuristic degrades it to Dijkstra. Choosing or computing the heuristic adds implementation complexity.

Scaling to a Real-Time Game Engine

1. Hierarchical Pathfinding (HPA*)

Divide the map into clusters/sectors. Pre-compute shortest paths within each cluster and between cluster borders. At query time, do a high-level search over clusters and refine locally. This reduces the effective graph size by orders of magnitude on large maps.

2. Navigation Meshes (NavMeshes)

Instead of a dense grid, represent walkable space as convex polygons. Pathfinding runs on the polygon graph (far fewer nodes), then a funnel algorithm smooths the path into straight-line segments. Standard in engines like Unity and Unreal.

3. Jump Point Search (JPS)

An optimization of A* for uniform-cost grids. JPS prunes symmetric paths by "jumping" over intermediate nodes, achieving 10–100× speedups while still guaranteeing optimality.

4. Incremental / Anytime Algorithms

D* Lite: re-plans efficiently when the map changes (dynamic obstacles). ARA*: returns a suboptimal path quickly, then refines it over successive iterations — useful when frame budgets are tight.

5. Multithreading & SIMD

Split independent pathfinding queries across worker threads. On the GPU, BFS-like algorithms map well to CUDA/compute shaders for thousands of simultaneous agents. Flow-field pathfinding computes a single field that all agents can share.

6. Caching & Amortisation

Cache recently computed paths and invalidate them only when the local map changes. Spread expensive re-plans over multiple frames to avoid frame-rate spikes.
